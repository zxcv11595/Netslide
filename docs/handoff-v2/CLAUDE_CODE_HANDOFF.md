- 적용 가능한 AGENTS.md와 Git 상태를 확인하고 관련 없는 변경을 보존한다. 일상적인 구현/검증마다 재승인을 요청하지 않는다.
- 별도 요청 없는 외부 공개, 유료 서비스 가입, Git 이력 변경은 하지 않는다.

## 기술 — 최신 변경

**Vite + TypeScript + HTML/CSS + SVG로 구현한다. 퍼즐 규칙과 스테이지·저장 데이터에 타입을 정의하고, 불필요한 `any` 사용을 피한다.**

- 앞선 JavaScript 전용 지침은 폐기한다. 기존 구조와 검증된 동작을 유지하며 TS로 전환한다. 이번 인계에서 전환을 완료했다고 간주하지 않는다.
- strict: true를 적용하고 tsc --noEmit을 검사에 포함한다. Vite 빌드만으로 타입 검사를 대신하지 않는다.
- 타일은 판별 유니온, 이동·보드·연결 결과·스테이지·저장 버전·진행 기록에는 명시적 타입을 둔다. handoff-v2/contracts.example.ts는 제안 초안이다.
- JSON/localStorage/URL 등 외부 입력은 unknown에서 런타임 검증 후 타입을 좁힌다. 타입 단언만으로 검증을 대신하지 않는다.
- DOM과 분리한 순수 규칙을 게임과 생성·검증 도구에서 공유한다. Node 도구/테스트의 TS 실행 방식도 문서화한다.
- 모바일 세로 우선, PC 브라우저 지원. 설치·가입 없이 정적 호스팅과 버전 있는 로컬 저장으로 시작한다.

## 퍼즐 규칙

- N×N 보드의 행·열을 버튼으로 한 칸씩 양방향 순환 이동한다. 끝 타일은 반대편으로 돌아오며 회전하지 않는다. 목표 타일도 줄과 함께 움직인다.
- 공급원 하나는 고정되며 해당 행과 열은 이동 불가. 잠금과 이유를 보여준다. 공급원 위치는 데이터에서 읽는다. 중앙 고정을 새 요구로 추가하지 않는다.
- 보드 안 인접 타일의 입구가 서로 마주 봐야 연결된다. 이동과 달리 경로는 반대편 가장자리로 이어지지 않는다.
- 방향 타일은 지정 입구로 들어온 흐름만 출구로 전달한다. 필요한 경우 탐색 상태에 진입 방향을 포함한다.
- 매 이동 후 현재 배치 전체에서 연결을 재계산한다. 이전 연결을 누적하지 않는다.
- **모든 햄스터가 동일한 클리어 목표이며 전부 동시에 연결해야 한다. 보너스 목표·타일·표시·보상은 삭제한다.**
- 조건 달성 시 완료 버튼을 활성화한다. 사용자가 눌러 확정하며 자동으로 다음 판에 가지 않는다. 다시 끊으면 완료도 비활성화한다.
- 시간/이동 제한과 초과 실패가 없다. 게임오버 화면도 없다.
- 무제한 되돌리기는 배치와 현재 이동 수를 함께 복원한다. 재시작은 시작 배치와 0수. 잠긴/무효 입력은 0수.

## 단계·진행·별

- 짧은 입문 뒤 초급·중급·고급을 선택하는 방향. 입문 판 수는 확정하지 않는다.
- **초급 3×3 / 중급 4×4 / 고급 5×5**. 각 크기 안에서 쉬운 판부터 어렵게 진행한다. 초급에 큰 격자를 섞지 않는다.
- 각 단계 안에서는 앞 판 기본 클리어로 다음 판 해금. 별 3개를 입장 조건으로 삼지 않는다.
- 단계 정의, 격자 크기, 판 ID/순서/개수는 데이터에서 읽는다. 35판·9판·단계 3개·최대 5×5를 코드에 고정하지 않는다.
- 6×6/7×7은 후속 가능성. 전용 조작안은 승인되지 않았으므로 이번 요구로 추가하지 않는다.
- 플레이 중 이동 관련 수치는 현재 이동 수만 표시한다. 연결 상태는 표시 가능. 별 예상치·별 목표 수·평가 기준은 숨긴다.
- 결과와 스테이지 목록에는 획득 별 1~3개와 개인 기록을 표시할 수 있다. **이동 수 기반 평가 방향이나 수치·계산식은 미확정**이다.
- 기존 star2/star3를 확정 기준으로 인계하지 않는다. 별 정책은 격리하고, 검토용 임시 기준이 필요하면 개발용임을 밝힌다. 운영 평가 확정 전에 임의 기준을 출시 규칙으로 굳히지 않는다.
- 최고 별과 최소 사용 이동 기록은 나빠지지 않는다. 신규 명세에 보너스 기록은 없다. 저장 변경 시 버전/콘텐츠 기록을 안전하게 분리하거나 변환한다.

## 판 생성·검증

- 연결된 정답 판 → 합법 이동 셔플 → 해답 재생 확인 → 제한 있는 풀이 탐색/검토 → 검증 판을 데이터로 저장.
- N번 셔플은 최단 N수 증명이 아니다. 현재 연결 BFS와 전체 상태 공간 탐색을 구분한다.
- 시간/상태 수 제한과 solved/exhausted/limit-reached를 구분한다. 제한 도달은 해답 없음/최단 증명이 아니다. 발견 해답과 최단 증명을 구분한다.
- 이미 풀린 시작판, 너무 쉬운 판, 중복 판을 거른다. 대칭 처리는 공급원·잠금·방향성을 보존해야 한다.
- **공통 최소 5수 같은 하한은 없다. 3×3은 4수 이하도 가능하다.** 크기별 생성 결과와 플레이 검토로 기준을 정한다. 과도하게 쉬운 일반 판은 별도 검토한다.
- 크기·목표 수·발견 해답 길이·최단 증명 여부·탐색량·제외 이유를 보고한다. 런타임 무거운 탐색 금지.
- 기존 보너스 판을 모두 일반 목표로 바꾸면 클리어 조건이 달라지므로 해답·순서·난이도·기록 버전을 다시 검증한다. 구버전 합격 보고서를 재사용하지 않는다.

## 애니메이션

- 과거 미리보기의 모든 효과가 승인된 것은 아니다. 어색한 연출은 제외한다. 별 등장 효과는 긍정 반응이 있었다.
- 줄 슬라이드/연결 변화는 실제 상태와 일치시킨다. 입력 경합과 transitionend 누락에 대비한다.
- 간식 이동은 판정에서 얻은 유효 경로를 사용한다. 정적 두 이미지 전환을 걷기/씹기 모션이라 부르지 않는다.
- 숨쉬기·성공 점프·몸 변형은 선택 검토 대상이며 필수 승인 효과가 아니다. 이번 시안에는 몸 변형을 넣지 않는다.
- 결과는 한 번 저장하고 연출 중 중단되어도 보존한다. 화면 전환 시 타이머/RAF/복제 노드를 정리한다.
- prefers-reduced-motion이면 장식 동작을 제거/단축한다. 긴 연출로 입력을 방해하지 않는다.

## 후순위 기능·수익화

- 오늘의 도전은 같은 한국 날짜에 검증된 같은 판을 제공한다. 같은 판 링크는 콘텐츠 버전+판 ID로 재현하고 과거 링크를 다른 판으로 바꾸지 않는다.
- 결과 공유는 획득 별·사용 이동 수·같은 판 링크. 보너스 항목 없음. Web Share 미지원 시 복사. 취소/실패는 성공 처리하지 않는다.
- 일일/공유는 핵심 이후 구현하며 일정에 따라 제외 가능. 미구현 버튼은 숨긴다. 재방문 효과를 보장하지 않는다.
- 무료+판 사이 전면 광고 후보. 보상형 광고 제외. 광고 제거는 구매 복원이 필요한 비소모성 결제로 후속 작업.
- 사업자/배포 경로 미정: 실제 SDK/운영 ID/추적 스크립트/가짜 구매 버튼을 넣지 않는다. 광고 어댑터 기본값은 비활성/no-op.
- 광고 기회는 결과 확인 뒤 다음 판 전환점에서 검토한다. 첫 진입/입문/플레이 중/되돌리기/재시작을 방해하지 않는다.
- 미준비/재고 없음/오류는 정상 진행. 광고 승인 때문에 공개를 늦추지 않는다. 실제 표시 때만 입력/오디오를 정지하고 종료 콜백으로 복귀한다. 중복 요청/오래된 콜백 차단. 빈도 수치는 미확정.

## Claude 작업 순서와 완료 증거

1. 지침/현재 상태 확인 → 기존 테스트 기준선 확보 → 기존 구조를 보존하며 TS 전환과 타입 검사 추가.
2. 규칙·결과·저장·공유·생성/검증·테스트의 보너스 개념 제거. 모든 목표 동시 연결 검증.
3. 크기별 단계 데이터/확장형 목록 반영. 별 정책 미확정 상태 분리, 플레이 HUD에서 별 기준 제거.
4. 세 화면/아트 적용, 새 규칙으로 판·해답·난이도 검증.
5. 핵심 흐름/저장/복원 → 필요한 연출 → 일정에 맞는 일일/공유/광고 연결부 → 브라우저 확인/빌드.

검증: 잠금/양방향 순환/회전 없음/목표 이동/가장자리 비연결/방향 역진입 차단/연결 해제/전체 목표/수동 완료/되돌리기 배치와 수/1별 다음 판/손상 저장/버전/중복 완료/콘텐츠 추가. 타입 검사와 빌드, 브라우저 결과를 구분해 보고한다. 미완료 탐색·미사용 기기·미연동 광고망을 합격으로 쓰지 않는다.
